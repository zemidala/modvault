# План разработки

## Принципы

- Игра всегда восстановима: операция либо завершается целиком, либо откатывается.
- Сначала ядро и тесты, потом окно. До этапа 8 всё работает из командной строки.
- Ядро (`core`) не знает об играх. Всё специфичное для игры живёт в её пакете.
- Каждый этап заканчивается проверкой на реальной игре.

### 1. Файловая основа (`core/fsx`)

Атомарная запись (временный файл → переименование), хеширование, жёсткие ссылки
с проверкой «тот же диск», перенос в Корзину, безопасное склеивание путей.

Готово, когда тесты покрывают обрыв записи, длинные пути, кириллицу в путях
и файл, занятый другим процессом.

Принято: хеш — SHA-256; вызовы Windows API — через `golang.org/x/sys`;
если Корзина недоступна, файл остаётся на месте и возвращается ошибка.

### 2. Хранилище и манифест (`core/store`, `core/manifest`, `core/profile`)

- Хранилище: исходный архив, распакованная версия, хеши файлов, метаданные.
- Несколько версий одного мода рядом.
- Манифест: для каждого файла в игре — чей он, какой хеш, когда развёрнут.
- Профили как списки «мод, включён, позиция».

Готово, когда мод можно добавить, получить список его файлов и удалить
без остатков, а база переживает обрыв записи.

### 3. Развёртывание и журнал (`core/deploy`, `core/journal`)

- Расчёт разницы между тем, что есть в игре, и тем, что должно быть по профилю.
- Применение ссылками, откат на копирование при разных дисках.
- Журнал: план записывается до начала, шаги отмечаются, при сбое — откат.
- Восстановление при запуске, если прошлый сеанс оборвался.
- Проверка целостности: чужие правки, пропавшие и лишние файлы.
- Конфликты файлов между модами с явным правилом, кто побеждает.

Готово, когда тест «убить процесс на каждом шаге» всегда приводит либо
к старому, либо к новому состоянию.

### 4. Плагин Darktide (`game/darktide`)

- Поиск игры: Steam, Xbox, ручной выбор.
- Разбор архива: обычный мод, вложенная `mods/`, `binaries/`, оверлей в корень,
  папки-обёртки, кривые имена.
- Чтение и запись `mod_load_order.txt`.
- Патч `bundle_database.data`: бэкап привязан к хешу оригинала, устаревший
  бэкап не накатывается никогда.
- Определение чужих патчеров и сосуществование с ними.
- Установка DML и DMF.

Готово, когда на чистой игре ставятся DML, DMF и десяток модов, игра
запускается, а после «выключить всё» файлы игры побайтно совпадают с исходными.

### 5. Командная строка и «усыновление» (`cmd/modvault`)

- Команды: установить, удалить, включить/выключить, развернуть, проверить,
  откатить, профили, состояние.
- «Усыновление»: существующая папка `mods/` переносится в хранилище
  без переустановки.
- Режим «показать, что будет сделано» без изменений.

Готово, когда существующую установку можно принять под управление и вернуть
обратно без потерь.

### 6. Правила и автосортировка (`rules`)

- Формат правил: обязательный порядок, «раньше/позже», зависимости,
  несовместимости, устаревшие.
- Сортировка с обнаружением циклов: цикл показывается, моды не теряются.
- Проверки с предложением исправления.
- Чтение внешних файлов правил как дополнительного источника.

Готово, когда на наборе из 100+ модов сортировка стабильна и ни один мод
не пропадает.

### 7. Nexus (`nexus`)

- Вход по личному API-ключу, ключ в хранилище учётных данных Windows.
- Приём ссылок `nxm://`, передача уже запущенной копии программы.
- Загрузка во временный файл, докачка, сверка хеша, затем — в хранилище.
- Проверка обновлений по ID файла, пакетно, с учётом лимитов.
- Обновление: новая версия ставится рядом, старая удаляется после успеха.

Готово, когда кнопка «Mod Manager Download» приводит к установленному моду,
а обрыв сети посреди загрузки ничего не портит.

### 8. Окно программы

- Технология — Wails 2: страница на HTML и CSS внутри WebView2, логика на Go,
  без Node и сборщиков; шрифты вшиты в программу.
- Оболочка окна сделана досрочно, сразу после этапа 1, чтобы результат был
  виден по ходу работы: `cmd/modvault-gui`, пакет `ui`. Пока ядро не
  подключено, она показывает демонстрационные данные с пометкой, а кнопки без
  ядра сообщают, на каком этапе заработают. Сборка:
  `go build -tags desktop,production -ldflags "-H windowsgui" ./cmd/modvault-gui`.
  Значок и манифест: `go run github.com/tc-hib/go-winres@latest make --arch amd64`
  в папке `cmd/modvault-gui`.
- Стиль — гримдарк: тёплые тёмные поверхности, латунные рамки, цвет пергамента,
  потёртая оранжевая шапка со знаком ZD.
- Главное окно: строка состояния под шапкой, блок «Требуют внимания», список
  модов профиля на всю ширину, карточка выбранного мода справа, план
  развёртывания внизу.
- Список модов, перетаскивание архивов, профили, порядок, проверки, журнал
  действий, настройки, мастер первого запуска.
- Русский и английский интерфейс.

Готово, когда всё, что умеет командная строка, доступно из окна, и ни одна
ошибка не остаётся только в логе.

### 9. Русификатор

Слой переводов поверх модов: подключается и снимается как обычный мод,
не трогая файлы оригинала.

### 10. Выпуск

Сборка релиза, сведения о версии в exe, контрольные суммы, самообновление,
инструкция.

## Риски

| Риск | Что делаем |
|---|---|
| Жёсткие ссылки не работают (другой диск, exFAT) | Определяем заранее, переходим на копирование с тем же манифестом |
| Обновление игры меняет формат бандла | Патч не применяется, если не найден ожидаемый якорь |
| Проверка файлов в Steam затирает развёрнутое | Проверка целостности это видит и предлагает развернуть заново |
| Лимиты Nexus API | Кэш ответов, пакетные запросы |
