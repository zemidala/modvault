# Разбор Servo-ModQuisitor-2

Заметки по исходникам [xsSplater/Darktide-Servo-Modquisitor-2](https://github.com/xsSplater/Darktide-Servo-Modquisitor-2)
версии 4.5.1 (2 октября 2026). Лицензия GPL-3.0: код не копируем, берём идеи.
Выводы сделаны по чтению кода, в работе программа не проверялась.

## Что это

Менеджер модов для Darktide: Go 1.27 + Fyne, около 27 тысяч строк, один автор.
Почти всё лежит в `package main` вокруг объекта `App`; отдельно вынесены
`checks` (проверки) и `sorter` (сортировка). Логика переплетена с интерфейсом,
состояние хранится в глобальных переменных. Привязка к Darktide зашита константами.

В поставке два файла данных:

- `mod_database.json` — 1121 мод: папка, шаблон имени файла на Nexus, автор,
  категория, ссылки, название и описание на 12 языках. В файле встречаются
  дубли ключей `pt-BR` / `pt-br`, строгие парсеры его не читают.
- `mandatory_obsolete_incompatible_dependencies.json` — обязательный порядок
  (16), пары «раньше/позже» (45), устаревшие (102), несовместимые пары (178),
  зависимости (142).

## Что стоит перенять

- **Патч `bundle_database.data`** (`bundle_patch.go`). В файле ищется 8-байтовый
  якорь `a3 3a 4a a4 af 26 a6 9b` (дескриптор boot-бандла `9ba626afa44a3aa3`),
  84 байта после него заменяются новым дескриптором с Lua-чанком `.patch_999`.
  Признаки чужих патчей: `.patch_999` (dtkit-patch), `9ba626afa44a3aa3.patch_001`
  (автопатчер DMA). При установленной `binaries/plugins/_dt_mod_autopatch.dll`
  источник истины — файл-флаг `mods/DISABLE_AUTOPATCHER`.
- **Виды архивов** (`mod_operations.go`): обычный мод; вложенная `mods/`;
  `binaries/` в корень игры; «оверлей» — архив повторяет корень игры
  (пример: Custom Assets, мод 1200); папка-обёртка вокруг всего; имена вида
  `ModName-222-33-4-5-666`; несовпадение имени папки и `.mod`-файла.
- **Защита при распаковке**: лимиты размера (архив 500 МБ, файл 500 МБ,
  всего 1 ГБ), запрет выхода за пределы папки назначения.
- **Формат `mod_load_order.txt`**: одна папка на строку, выключенный мод —
  строка с префиксом `-- `.
- **Nexus**: API v1 (`/games/warhammer40kdarktide/mods/{id}/files.json`,
  `.../files/{file}/download_link.json`), для бесплатных аккаунтов ссылка
  требует `key` и `expires` из `nxm://`. OAuth с PKCE, обратный адрес
  `localhost:31337/callback`. Токены в хранилище учётных данных Windows.
- **`nxm://`**: регистрация в `HKCU\Software\Classes\nxm`, второй экземпляр
  передаёт ссылку первому через локальный порт.
- **Запуск игры без лаунчера**: `Darktide.exe` с аргументами
  `--backend-auth-service-url https://bsp-auth-prod.atoma.cloud` и
  `--backend-title-service-url https://bsp-td-prod.atoma.cloud`; Steam AppID 1361210.
- **Парсер Lua-файлов `.mod`** и редактор `user_settings.config`.

## Где он ненадёжен

| Проблема | Что происходит | Последствие |
|---|---|---|
| Устаревший бэкап бандла | `.bak` создаётся только если его нет, а выключение модов переименовывает его поверх рабочего файла | После обновления игры бандл откатывается на старую версию |
| Циклы в правилах | Топологическая сортировка выдаёт только узлы без цикла | Моды из цикла молча пропадают из `mod_load_order.txt` |
| Нет учёта установленных файлов | Файлы копируются в `mods/`, `binaries/` и корень игры без записи | Нельзя чисто удалить «оверлей», нельзя узнать, чей файл |
| Обновление мода | Старая папка уходит в Корзину до распаковки нового архива | При битом архиве мод исчезает |
| Профили — полные копии | Переключение копирует всю папку модов и уносит текущую в Корзину | Медленно, занимает место, есть окно без `mods/` |
| Неатомарная запись | Порядок загрузки, бандл, конфиг пишутся прямо в целевой файл | Сбой оставляет обрезанный файл |
| Загрузки | Файл качается сразу в конечное имя, хеш не сверяется | Оборванная загрузка выглядит как готовый архив |
| Поиск файла на Nexus | По вхождению подстроки в имя файла | Для модов с несколькими файлами может выбрать не тот |
| Проверка обновлений | Один запрос на мод, последовательно; сама проверка требует входа | Медленно, упирается в лимиты |
| Ошибки | Многие пишутся только в лог-файл | Пользователь не узнаёт о сбое |

## Как это отражено в плане

- Устаревший бэкап, чужие патчеры — этап 4.
- Учёт файлов, профили-списки, атомарность, откат — этапы 1–3.
- Циклы в сортировке — этап 6.
- Загрузки и поиск файла по ID — этап 7.
